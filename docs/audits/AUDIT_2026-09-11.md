# 5. Search algorithm review

- Live run6 is still PUCT-50 (§4). The Gumbel path (`search.kind gumbel`) is the wave-1/2 dialect:
  sequential halving over `gumbel_m 16`, completed-Q target, `c_scale 1.0`, `c_visit 50`,
  root over the full legal prior without materializing every child, interior cap
  `MAX_CHILDREN_PER_NODE 1024` in a 4M-node pool.
- **Run at scale for the first time this leg** (PERF-3b, 320/64 PCR): the search serves ≈5.6M
  leaves/h on the RTX 5080 at 54.6% batch fill with 16 workers; batch fill under 60% says the
  server, not the search, is the next lever — consistent with R347(e)'s carded
  single-threaded-server ceiling.
- **α reading:** 98.9% of rows carry a tail (mean 0.0006, p90 0.0002), and rows with **α = 1.0**
  exist — no target mass on any of the 16 explicit entries. Under sequential halving the visited
  candidates are the sampled ones, so a row whose explicit entries carry nothing is either a
  root whose sampled set was empty of the improved-policy mass or a construction edge case.
  Not adjudicated (CARD-ALPHA-MAX-ROWS); the KL witness (`gumbel_sparse_row_kl.rs`) passes in
  gate 2a but bars a MEDIAN, which a max-1.0 row does not move.
- The engine bills `sims_per_sec` at `n_sims_full` under PCR (an over-bill by design); the
  reading is instantaneous per drain interval (3,198 / 6,381 / 12,705 across three samples) and
  should not be quoted as throughput; positions/h is.

# 6. Training pipeline

- Trainer: bf16 autocast on the graph path (LAW-06), microbatch caps `max_edges 4.5M /
  max_nodes 170k` (run6), batch 256 → one microbatch of ≈2.85M edges at r8 and ≈5.3 s/step on
  the RTX 5080. **The block is trainer-bound** (678 steps/h against 1,125 games/h at 1 step per
  game): 25k steps ≈ 37 h, inside R347(b)'s 2–2.5 day prediction.
- Non-finite handling (AUDIT-2 P0-1): repaired — `clip_and_step` refuses `optimizer.step()` on a
  non-finite clip norm and zeroes gradients; an all-non-finite batch (`contributing == 0`) refuses
  the step and does not advance `self.step`, the scheduler or EMA; `skipped_steps` reconciles.
- Resume (AUDIT-2 P0-3/P0-4/P1): identity drift refused by `_refuse_identity_drift`; full
  checkpoints load `strict=True`; checkpoint and ring writes are atomic (`atomic_write`,
  `atomic_save`); a periodic checkpoint is a resume bundle. Residual: §8 P1-1.
- Warm start: `maybe_warmstart_gnn_from_bc` reads the BC artifact through `load_checkpoint`,
  which re-validates the stamped config against the live schema — §1's break. The strip path
  (`strip_and_restamp`) synthesises a current-schema config and is the sanctioned migration.
- On a CPU host the trainer's bf16 GEMMs are emulated (72× measured on Zen 2); no run uses that
  path, every CPU-trainer test does.

## P0-A — the drain dropped R347(a)'s tail mass (FIXED `79b2b2c3`)

**Finding.** `collect_graph_data` returned a row without `tail_mass`; `push_graph_position`
defaulted it to 0.0. Every sparse Gumbel row reached the ring with α = 0; the first row with a
real tail (Σ explicit = 0.9947) was refused at insert and killed the producer.
**Impact.** Under `search.kind gumbel` no run could survive its first non-trivial row, and the
LAW-18 α line published 0 as "measured". **Repair.** The drained row carries the record's tail
before the trailing game id; the push forwards it by keyword; the arity parity test binds both
sides. **Confidence: High (measured on the box).**

## P0-B — the drain unpacked a row the engine no longer sends (FIXED `92643671`)

**Finding.** DELETE-1 removed `seeded`/`solver_fires` from the Rust `GameResultRow` and the `.pyi`;
`pool_drain.run_stats_loop` still unpacked 10 and every default-tier fake scripted 10.
**Impact.** The real self-play seam died on its first completed game; only the integration tier
could see it. **Confidence: High (measured).**

## P0-C — run6's warm-start artifact refuses under the live schema (OPEN, one owed row)

**Finding.** `load_checkpoint` runs `RunConfig.model_validate` on the stamped config; the BC
artifact was stamped before CONFIG-1/DELETE-1 and carries 49 keys the schema now forbids.
**Impact.** run6 cannot warm-start on any tree past wave 2; every comparison to the pre-registered
net would be against a fresh init if the row were loosened. **Recommendation.** Move
`identity.warm_start.checkpoint` to the strip `run6_00006500_ca1afb71.ckpt` (net hash unchanged)
at the re-mint; do not loosen the loader. **Confidence: High.** **Location:**
`train/checkpoints.py::load_checkpoint`, `train/warmstart.py::apply_bc_warm_start`.

## P0-D — the gate set re-synced the venv it gated (FIXED `8dfa8b5f`)

**Finding.** Every `$UV run` in `run_all.sh` re-synced to the default groups; on a box that
swaps the cuda extra back to the CPU wheel between gates. **Impact.** No box gate run has ever
gated a CUDA venv; "19/19 green on the box" in the record was measured on the CPU wheel.
**Repair.** `UV_NO_SYNC=1` exported by the runner, the torch build printed on every run.
**Residual.** Gated as built on `+cu128`, ten rows fail on CPU-torch assumptions (P1-2).
**Confidence: High (measured).**

## P1-1 — `RESUME_CHECKPOINT_OWNED_KEYS` is dead text

**Finding.** `orchestrator.py` lists flat names (`lr`, `encoding`, `res_blocks`, …); the config
passed to `build_resume_config_overrides(config, config, …)` is nested (`train`, `identity`,
…), so no key is ever filtered and every top-level section of the launch config overrides the
baked one. `lr` alone is handled explicitly downstream (`lr_prov.override_ignored`).
**Impact.** On resume, `train.weight_decay`, `lr_schedule`, `eta_min`, `total_steps` and the
rest of `train.*` follow the launch config, not the checkpoint, silently. Identity is safe
(`_refuse_identity_drift`). **Recommendation.** Either declare the owned set in nested form and
prove it filters (a producer test that plants a differing `train.eta_min` and asserts the baked
value wins), or delete the set and state that launch wins. **Confidence: High.**
**Location:** `src/mantis/train/orchestrator.py::RESUME_CHECKPOINT_OWNED_KEYS`.

## P1-2 — ten default-tier rows assume a CPU torch

**Finding.** With a CUDA build, `tests/model/conformance/test_arch_states_its_memory_envelope.py`
(8 rows) and `tests/model/test_gnn_v2_witnesses.py::test_both_arches_FORWARD_on_a_real_wire_position`
(2) fail with "Expected all tensors to be on the same device": the net lands on CUDA while the
tests' tensors stay on CPU; the `slow` harness rows fail the same way through
`test_local_gate_runner`. **Impact.** The gate set cannot be green on a CUDA venv until the tests
state their device. **Recommendation.** Build the oracle nets on an explicit device in the tests
(the device is a config fact — the same rule the run follows). **Confidence: High (measured on
the box).**

## P1-3 — the integration tier is host-bound by LAW-06

**Finding.** The CPU trainer runs bf16 autocast; on a CPU without AVX-512 BF16 a GEMM at the
trainer's shape is 72× slower than fp32 (measured), so real-boot rows take minutes each and the
tier never finishes on the dev box; it finishes in ~25 min on the box. **Recommendation.** A
ruling: the tier is a box gate, or the OC-7 row is `slow`, or LAW-06 gains a CPU-only carve-out
for tests (a law amendment), or a minted CUDA smoke profile for the dev box's own GPU.
**Confidence: High.** **Location:** `train/trainer/core.py` `_autocast_enabled`, `model/amp.py`.

## P1-4 — the durability halt had no test seam and refused every test drive

**Finding (FIXED `9137ab1a`).** R347(d)'s rc 16 read `/proc/mounts`; pytest's tmp base is
tmpfs/overlay, so every preflight-driving row failed wherever it ran. **Repair.** The preflight
reads a planted table only through `MANTIS_PREFLIGHT_MOUNTS_TABLE`, the reading names the table,
and `mantis.run` refuses a stamp from any table but the kernel's — a seam that launches nothing.
